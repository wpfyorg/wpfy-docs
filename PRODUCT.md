# Product

## Register

product

## Users

Ubuntu VPS operators, WordPress developers, and agencies use the wpfy knowledge base while installing, operating, debugging, and recovering Docker-backed WordPress sites. They are usually trying to complete a concrete server task, verify a command, or understand the safety model before touching production infrastructure.

## Product Purpose

The wpfy knowledge base is the public documentation surface for a Docker-first WordPress/server administration CLI. It should make the flat operator commands easy to find, explain when grouped compatibility commands still exist, and help readers move from install to site creation, backup, restore, SSL, cron, SMTP, and troubleshooting without exposing private project paths or internal notes.

## Brand Personality

Quiet, operational, and exact. The interface should feel like a trustworthy field manual for server work: calm enough for production incidents, direct enough for repeated use, and specific enough to avoid marketing vagueness.

## Anti-references

Avoid startup landing-page spectacle, oversized decorative cards, emoji-led documentation, dark blurred hero imagery, generic SaaS gradients, vague "modern DevOps" copy, and UI patterns that bury commands behind promotional content.

## Design Principles

- Put the command path first.
- Separate implemented behavior from planned or deferred behavior.
- Prefer dense, scannable documentation over campaign-style storytelling.
- Preserve public safety by excluding private paths, credentials, and internal-only workflow details.
- Make mobile navigation and code reading practical for operators using a laptop, tablet, or phone during maintenance.

## Accessibility & Inclusion

Target WCAG 2.2 AA practical behavior: visible focus states, readable text contrast, keyboard-accessible navigation, reduced-motion support, responsive code blocks, and link/button labels that remain clear without visual decoration.
