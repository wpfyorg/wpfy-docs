# KB Design Spec: docs.wpfy.org

**Date:** 2026-06-15
**Status:** Approved
**Reference:** https://demyx.sh/kb/

## Summary
Build a VitePress-powered knowledge base at docs.wpfy.org. MotherDuck-style custom theme, GitHub Pages deployment, 32 articles across 6 categories. Existing `docs/` stays as internal specs; new content lives in `kb/`.

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Static generator | VitePress | Reads existing markdown, built-in search/sidebar/dark mode, minimal setup |
| Styling | Custom MotherDuck theme | Brand consistency with marketing site (cream/sky-blue, doodles, typography) |
| Deploy | GitHub Pages + Actions | Free, automatic on push, no server maintenance |
| Source location | New `kb/` dir at repo root | Keeps `docs/` as internal specs, clean separation |
| Content format | Markdown with frontmatter | Source of truth, version-controlled alongside code |

## Article Template

Every command article follows this structure:

1. **Purpose** — one-sentence description of what the command does
2. **Syntax** — code block with all invocation forms
3. **Flags/Options** — table of every flag with type, default, description
4. **Examples** — real-world shell snippets with expected output
5. **Expected Behavior** — what files, services, registry state it touches
6. **Failure Modes** — error conditions, how they're surfaced, recovery steps
7. **Related Commands** — cross-links to sibling articles

Reference pages follow a narrative structure (no flags/syntax table).

## VitePress Config

- **Search:** Built-in local search (`search: { provider: 'local' }`)
- **Nav:** Logo → wpfy.org, links to GitHub, marketing site
- **Sidebar:** Category-collapsible, auto-generated from directory structure
- **Theme:** Custom CSS extending VitePress default with MotherDuck palette
- **Dark mode:** VitePress built-in toggle, custom colors for both modes

## Deploy Workflow

```yaml
# .github/workflows/deploy-kb.yml
on:
  push:
    branches: [main]
    paths: ['kb/**', '.github/workflows/deploy-kb.yml', 'package.json']
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
      - run: npm ci
      - run: npm run docs:build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: kb/.vitepress/dist
  deploy:
    needs: build
    uses: actions/deploy-pages@v4
```

CNAME: `docs.wpfy.org` → `wpfyorg.github.io`

## Execution Phases

2. **Write new** — 14 new command articles from source code

6. **CI/CD** — GitHub Actions deploy workflow

## Non-Goals
- No WordPress backend (that would be ironic)
- No i18n in v1
- No versioned docs (until v2 API surface exists)
- No comments/feedback widget
- Existing `docs/` directory remains untouched as internal specs

## Anti-Patterns (from project conventions)
- Never print secrets in examples
- Never claim perfect isolation
- Commands must be documented as idempotent where implemented
- SSL commands must document preflight requirement
